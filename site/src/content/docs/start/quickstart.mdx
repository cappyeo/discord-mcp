This is the shortest verified path from a local install to a real Discord tool call. You will
first prove the connection with a read-only request, then send one message to a test channel.

## Prerequisites

- **Node.js 22.12 or newer** (`node --version`)
- a Discord bot installed in a private test server
- its token and the test server's ID
- Claude Desktop, or another stdio MCP client covered in [Client setup](/discord-mcp/start/client-setup/)

If you do not have the bot yet, complete [Create a Discord bot](/discord-mcp/start/create-discord-bot/)
before continuing.

<Steps>

1. **Install the CLI.**

   ```bash
   npm install -g @discord-mcp/cli
   discord-mcp --version
   ```

2. **Generate a Claude Desktop config snippet.**

   ```bash
   discord-mcp init --client claude-desktop
   ```

   In an interactive terminal, enter the token when prompted. This avoids putting it in shell
   history. If the output contains the literal `${env:DISCORD_TOKEN}`, replace that placeholder
   with the real token in your local config; do not assume every client expands it.

3. **Merge the snippet into Claude Desktop.**

   Add the generated `discord-mcp` entry to the existing top-level `mcpServers` object:

   | OS | Claude Desktop config |
   |---|---|
   | macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
   | Windows | `%APPDATA%\Claude\claude_desktop_config.json` |
   | Linux | `~/.config/Claude/claude_desktop_config.json` |

   <Aside type="danger">
   Do not point `init --output` at an existing client config. With `--force`, it writes a new
   top-level document and can remove other configured MCP servers. Merge the printed entry.
   Once the file contains a token, never commit or share it.
   </Aside>

4. **Validate the token and Discord connection.**

   `doctor` reads the current terminal environment, not the client config. Set the token only
   for this terminal and run the online checks:

   ```bash
   export DISCORD_TOKEN="YOUR.TOKEN.HERE"          # macOS / Linux
   discord-mcp doctor --online
   ```

   ```powershell
   $env:DISCORD_TOKEN = "YOUR.TOKEN.HERE"          # Windows PowerShell
   discord-mcp doctor --online
   ```

   Continue on exit `0`; inspect warnings on exit `1`; fix failures on exit `2`.

5. **Restart Claude Desktop and prove the connection read-only.**

   Fully quit and reopen Claude Desktop. Ask:

   > Use `users_get_current` and tell me the bot username and ID. Do not call any other tool.

   The tool needs no arguments. A successful result identifies the same bot you created in
   the Developer Portal.

6. **Discover the channel ID.**

   Replace the example with your copied server ID:

   > Use `channels_list` with `guild_id` `999000999000999000`. Return the ID for `general`.

   The result includes `channels[].id`. Keep the ID for the next step.

7. **Send one test message.**

   > Use `messages_send` with `channel_id` `112233445566778899` and content
   > `hello from discord-mcp`.

   A successful result contains `message_id`, `channel_id`, `jump_url`, and `timestamp`.
   Open `jump_url` to verify the message in Discord.

</Steps>

<Aside type="caution">
`messages_send` is a write, but it is not destructive and is not confirmation-gated. It can
execute on the first call. Keep onboarding inside a test server and grant the bot only the
Discord permissions it needs.
</Aside>

## What you proved

- The MCP client can spawn discord-mcp over local stdio.
- The token authenticates against Discord.
- The bot can read the test guild's channel list.
- A concrete `channel_id` can be passed into a write tool and its structured result reused.
