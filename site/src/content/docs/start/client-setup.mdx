This lesson covers the default **local stdio MCP** setup for clients that can spawn an MCP
server as a subprocess. The `init` command generates a client-specific configuration fragment;
Codex receives TOML and the other first-class clients receive JSON. It prints the fragment
by default, so you stay in control of the file you merge it into.

<TutorialPreCheck>

- Confirm that `discord-mcp --version` works in your terminal.
- Keep your bot token available in a password manager or another private location.
- Find your client's local MCP configuration file before generating a snippet.

</TutorialPreCheck>

<Aside type="caution">
`init` does not edit your client config and never prompts for a real token. Omission always generates
an environment reference. With `--discover-guilds`, the current `DISCORD_TOKEN` is sent only to Discord
to verify the bot and its guild membership; it is not copied into the generated fragment. The Codex
fragment forwards `DISCORD_TOKEN` from the environment; the JSON fragments use `${env:DISCORD_TOKEN}`
only when the client supports expansion. Do not pass the token with `--token`, because command arguments
can remain in shell history and process inspection.
</Aside>

## Choose your client

<ClientTabs>
  <div slot="claude-desktop">

  ```bash
  discord-mcp init --client claude-desktop
  ```

  Merge the printed `discord-mcp` entry into the `mcpServers` object, then fully quit
  and reopen Claude Desktop.

  | OS | Config file |
  | -- | ----------- |
  | macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
  | Windows | `%APPDATA%\Claude\claude_desktop_config.json` |
  | Linux | `~/.config/Claude/claude_desktop_config.json` |

  </div>
  <div slot="claude-code">

  ```bash
  discord-mcp init --client claude-code
  ```

  Merge the output into `~/.claude.json` for user-level configuration, or into
  `<project>/.mcp.json` for a project. Claude Code also supports its managed
  `claude mcp add` workflow; use the generated snippet when you prefer explicit JSON.

  </div>
  <div slot="codex">

  ```bash
  read -rsp 'Discord bot token: ' DISCORD_TOKEN && printf '\n'
  export DISCORD_TOKEN
  discord-mcp init --client codex --tool-surface progressive --discover-guilds
  ```

  ```powershell
  $env:DISCORD_TOKEN = Read-Host 'Discord bot token' -MaskInput
  discord-mcp init --client codex --tool-surface progressive --discover-guilds
  ```

  Merge the TOML fragment into `~/.codex/config.toml`. It uses
  `env_vars = ["DISCORD_TOKEN"]`, so Codex forwards the token from its launch
  environment instead of storing it in `config.toml`. Guild discovery verifies
  the caller-owned bot and adds an `ALLOWED_GUILDS` server-side boundary, not
  merely a client-side filter. If the bot can see multiple guilds in a
  non-interactive run, rerun with `--allowed-guilds <id>` to make the target
  explicit.

  Start Codex from a terminal where the token is set:

  ```bash
  export DISCORD_TOKEN="Bot YOUR_DISCORD_BOT_TOKEN"
  codex
  ```

  ```powershell
  $env:DISCORD_TOKEN = "Bot YOUR_DISCORD_BOT_TOKEN"
  codex
  ```

  This is the local stdio setup for the Codex CLI and IDE extension. Start a new
  Codex session after changing its configuration.

  </div>
  <div slot="cursor">

  ```bash
  discord-mcp init --client cursor
  ```

  Merge the output into `~/.cursor/mcp.json` for global access or
  `<project>/.cursor/mcp.json` for one project. Restart Cursor after changing it.

  </div>
  <div slot="generic">

  ```bash
  discord-mcp init --client generic
  ```

  The output is a standard `mcpServers` block. Place it where your MCP client's own
  documentation expects stdio server configuration.

  </div>
</ClientTabs>

The generated snippet uses the current CLI path, so it works immediately from the
installation that created it. If you later move or replace that installation, generate
a fresh snippet instead of editing an absolute path by hand.

Once the snippet contains a real token, treat the whole client config as a secret: do not
commit, share, or screenshot it.

After restarting, confirm that your client can list discord-mcp's tools without a startup
error. Unit 3 performs the online token diagnostic and the first authenticated tool call, so
you do not need to expose the token to a second process yet.
