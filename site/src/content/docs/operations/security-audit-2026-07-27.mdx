## Why the raw count overstates exposure

`pnpm audit` walks the dependency graph. It cannot tell that most of the
vulnerable code is never loaded by what discord-mcp actually ships. Grouped by
reachability:

### Not reachable — the SDK's HTTP transport, which this project does not ship

discord-mcp is **stdio-only at v1.0.0** (see
[v1.0.0 readiness → What is NOT in v1.0.0](https://github.com/cappylab/discord-mcp/blob/main/docs/v1.0.0-readiness.md)).
`@modelcontextprotocol/sdk` bundles a Streamable-HTTP server transport whose
dependency subtree is installed but never imported by `startStdio`.

| Package | Advisories | Reached via |
| ------- | ---------- | ----------- |
| `hono` | 17 | `@modelcontextprotocol/sdk` → `@hono/node-server` |
| `@hono/node-server` | 1 | `@modelcontextprotocol/sdk` |
| `body-parser` | 1 | `@modelcontextprotocol/sdk` → `express` |
| `qs` | 1 | `@modelcontextprotocol/sdk` → `express` → `body-parser` |
| `ip-address` | 1 | `@modelcontextprotocol/sdk` → `express-rate-limit` |

That is **21 of the 50** advisories in packages that only execute if you
instantiate an HTTP transport. Shipping HTTP transport in a v1.x minor would
make all of them live; until then they are inert.

### Not reachable by default — OpenTelemetry, off unless `OTEL_ENABLED=true`

The OTel SDK is not merely idle when disabled: `mcp-server` skips SDK boot
entirely, so these modules are never imported.

| Package | Advisories | Reached via |
| ------- | ---------- | ----------- |
| `@grpc/grpc-js` | 2 | `@opentelemetry/sdk-node` → OTLP gRPC exporter |
| `protobufjs` | 4 | `@grpc/grpc-js` → `@grpc/proto-loader` |

**6 advisories.** They become live only for operators who set
`OTEL_ENABLED=true`, and only additionally when
`OTEL_EXPORTER_OTLP_PROTOCOL=grpc`.

### Not reachable at runtime — docs-site build tooling

The `site` package is `private: true`, is never published, and does not run in
any deployment. Its advisories affect anyone building the docs locally, not
anyone running the server.

| Package | Advisories |
| ------- | ---------- |
| `astro` | 8 |
| `vite` | 2 |
| `js-yaml` | 2 |
| `sharp`, `svgo`, `postcss`, `esbuild`, `devalue` | 1 each |

**17 advisories**, all build-time-only.

### Loaded on the default path

| Package | Advisories | Assessment |
| ------- | ---------- | ---------- |
| `fast-uri` | 4 | Reached via `@modelcontextprotocol/sdk` → `ajv`, which the SDK's `Server` imports unconditionally for JSON-Schema validation. All four advisories are URI parsing / host-confusion issues. discord-mcp feeds `ajv` only its **own** tool schemas, which contain no `$ref` to an attacker-controlled URI, so there is no path from Discord content or agent input into the vulnerable parser. |
| `@opentelemetry/core` | 1 | Unbounded memory allocation in W3C Baggage propagation. Reached via `@opentelemetry/resources`, which `mcp-core` imports statically for `buildResource` — so the module **is** loaded even with `OTEL_ENABLED=false`. The vulnerable code path is baggage-header parsing, which only runs once a propagator is installed by the OTel SDK, i.e. only when telemetry is on. Loaded but not exercised by default. |

**5 advisories loaded, 0 with a demonstrated path from untrusted input.**

<Aside type="note">
`ws` and `undici` are the two packages an auditor would expect to find on the
default live path, since they carry the WebSocket and HTTP traffic. Neither
appears in the 2026-07-27 run: `undici` ships inside Node as the `fetch`
implementation rather than as a workspace dependency here, and `ws` is a
`discord.js` transitive — `discord.js` is not installed at all unless you opt
into Gateway mode. Re-check both on every audit; a future advisory on either
would land squarely on the default path.
</Aside>

## Summary

| Bucket | Advisories | Live in a default stdio deployment? |
| ------ | ---------- | ----------------------------------- |
| SDK HTTP transport subtree | 21 | No — HTTP transport not shipped |
| OTLP gRPC exporter subtree | 6 | No — `OTEL_ENABLED=false` by default |
| Docs-site build tooling | 17 | No — `site` is private, build-time only |
| `ajv` / `fast-uri`, `@opentelemetry/core` | 5 | Loaded, but no untrusted-input path |
| Remaining / unclassified | 1 | — |

**0 critical.** **0 advisories with a demonstrated exploit path** from Discord
content, agent input, or operator config in the default stdio configuration.

| Priority | Finding | Status |
| -------- | ------- | ------ |
| P0 | — | None |
